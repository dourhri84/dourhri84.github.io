# Validation against a physical Apache Cassandra cluster

This folder holds the material to compare CassLab with a real Apache Cassandra 5.0 deployment. This is the validation reported in Section 4 of the CassLab paper.

## Test bed

The test bed uses eight identical workstations (Ubuntu 23.04):

| Machine | Role |
|---|---|
| M1–M3 | Cassandra nodes of dc1 (cluster C1 and cluster C2) |
| M4–M6 | Cassandra nodes of dc2 (cluster C2 only) |
| M7 | Client: CassLab in a browser, `cqlsh` |
| M8 | Spare node, bootstrapped into C1 for the rebalancing test |

The two clusters are configured as follows:

| Cluster | Topology | Keyspaces |
|---|---|---|
| C1 | 1 DC, 3 nodes, 1 token per node, `SimpleStrategy` | `c1_rf1`, `c1_rf2`, `c1_rf3` |
| C2 | 2 DCs × 3 nodes, 2 racks per DC, 16 vnodes per node, `NetworkTopologyStrategy` | `c2_rf1`, `c2_rf2`, `c2_rf3` (RF per DC) |

The same clusters must be built in CassLab, in Advanced mode with the 64-bit hash. In CassLab, nodes are numbered in order: Node 1 is M1, Node 2 is M2, and so on.

## Files

| File | Content |
|---|---|
| `config/C1_*.txt`, `config/C2_*.txt` | Per-machine settings: `cassandra.yaml` keys and `cassandra-rackdc.properties`. The `initial_token` values are the tokens generated by CassLab. |
| `config/C1_M8_bootstrap.txt` | Settings of the node added during the rebalancing test |
| `schema_and_data_C1.cql`, `schema_and_data_C2.cql` | Keyspaces, tables, and the 40 partition keys (10 ASCII, 10 accented, 10 `int`, 10 composite) |
| `expected_casslab.csv` | CassLab's predictions for every (keyspace, key) pair: token, and replicas in order (first = primary) |
| `collect_and_compare.py` | Queries the real cluster (`cqlsh`, `nodetool getendpoints`) and compares it with `expected_casslab.csv` |

## Procedure

1. Install Apache Cassandra 5.0 and OpenJDK 17 on M1–M6 (and M8).
2. On each machine, before the **first** start, apply its `config/…` file. Set the IP addresses where the file shows `<IP of Mx>`.
3. Start the seeds first (M1, then M4 for C2), then the other nodes one at a time.
4. Check the tokens with `nodetool ring` and the ownership with `nodetool status`. Compare them with CassLab's Cluster Configuration and Virtual Nodes modules.
5. Load the schema and the data: `cqlsh <node-ip> -f schema_and_data_C2.cql`.
6. Collect the outputs and compare them. On M1, create `machines.csv` (columns `name,ip`), then run `python3 collect_and_compare.py --cluster C2 --machines machines.csv`.
7. Failures: stop nodes with `sudo systemctl stop cassandra`. Wait until `nodetool status` shows them as `DN`. Then, in `cqlsh`, run `CONSISTENCY <level>` followed by a write and a read. Record success, or `Unavailable`. Compare with CassLab's Failure Simulation module.
8. Rebalancing (C1): record the replicas of `c1_rf1`. Start M8 with `config/C1_M8_bootstrap.txt`, run step 6 again, and count the keys whose owner changed.

To repeat the procedure for C1, wipe the data directories of M1–M3 and use the `C1_*` files.

> The scripts were generated from CassLab's engine. They have not been run on this test bed yet; adapt the paths and addresses to your installation. The collected outputs (`results_*.csv`, logs) should be added to this folder once the experiment is done.
